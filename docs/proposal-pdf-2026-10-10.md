# Proposal PDFs and tracking

Private Bandevi sales/client workspace only. No THG travel, B2B, white-label or CRM changes.

Staff Proposals navigation opens an authenticated tracker across all accessible project revisions. It shows draft, awaiting acceptance, expiring within seven days, expired and accepted counts. Expiring is a subset of awaiting; counts are independent of search. Published revisions at or before the current timestamp are expired. Accepted records remain accepted after expiry. All revisions, withdrawn and superseded filters retain history. Search covers proposal/project title, enquiry reference and client email. Pages contain 25 rows with stable ordering. Agents are restricted to currently assigned enquiries; QA records are excluded.

Each proposal card and tracker row has Download proposal PDF. The server rechecks the current staff/client lane, project membership and proposal visibility, then generates an attachment with no-store/nosniff/noindex headers. Clients cannot download drafts or withdrawn revisions that were never published. Own published historical revisions remain readable with clear status. The project view now applies the same unpublished-history boundary. Client accounts cannot use staff tracking/download APIs and staff cookies cannot authorize client APIs.

PDFs include the BG/company brand, recorded project/client/reference/revision, ISO currency and exact decimal value, dates in IST, scope, terms, and any recorded acceptance. They distinguish unpublished drafts, expired, withdrawn and superseded revisions. They contain no internal owner, notes, actor, SMTP details, payment claims, invented tax or prices. Text is escaped before ReportLab paragraph markup. A4 pages repeat branding and numbered footers. The embedded Vera fonts support their available character set; unsupported characters produce an explicit export error rather than an incomplete PDF. Original text remains accessible in the workspace.

Dependencies: reportlab 4.4.9 in a Bandevi-only virtual environment at `/srv/bandeviglobalgroup/pdf-runtime`; pypdf 6.10.0 is a test-only parser. No global Python packages are changed. A Bandevi systemd drop-in uses that virtual environment while preserving the original unit's user, sandboxing, environment and ports. The drop-in and application can be rolled back independently without schema changes or data restoration.

Validation: six isolated PDF/tracking backend tests cover snapshot values/status, no internal data, client/staff lanes, draft visibility, expiry/supersession/acceptance, tracker filters, current agent assignment, literal/long text and unsupported glyph rejection. Seven synthetic proposal browser scenarios cover navigation, pagination, filters, staff/client downloads and three viewport widths; the existing inbox/public suites also run. Poppler renders the accepted two-page sample; both pages were visually inspected with branding, text and footer intact.

Production release requires a clean expected baseline, verified application/configuration/SQLite backup, tested merged SHA and isolated runtime check. Activate only the Bandevi drop-in, restart Bandevi, verify health/assets/privacy, generate a synthetic in-memory PDF as the service user, run backup/monitor, and perform live read-only tracking checks. No real project, proposal, acceptance or outbound test email is created during verification.
