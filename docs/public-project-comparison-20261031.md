# Side-by-side Project Comparison — 31 October 2026

The existing `/project-shortlist/` page gains optional comparison of two or three eligible project references already in the current shortlist. There are four source-supported references: BANDEVI website, Trip Sarathi, MaximTrip and TripOdeal. Services, guides and project-directory pages remain in the shortlist but do not become comparison columns. Visitors add references using the existing Site Search/Shortlist controls. The shortlist still allows up to five public pages and retains its existing manual Save and Clear behavior.

The new section has manual **Compare** and **Clear comparison** controls. Checkbox changes never generate or update a table automatically. When choices differ from the displayed comparison, the status identifies the still-displayed references and asks for Compare. At three checked references the remaining checkbox is disabled; the event handler independently enforces that maximum. Clear comparison removes the in-tab choices and table while preserving the current and saved shortlist, pending handoffs, readiness choices, saved brief and other browser storage. The comparison module does not access storage, cookies, analytics, forms or APIs.

Eligible references come from the existing widget's visible current shortlist, rather than a second saved selection. Compare reads that context again at the action. An unsaved shortlist can be compared for discussion, while the existing Save-before-brief-review rules continue to apply. If a current reference is removed, or another tab clears/reloads the clean shortlist, unavailable checkbox selections are discarded and a displayed comparison containing a removed reference is hidden. The visitor must choose current references and Compare again. Comparison never prepares or consumes a brief handoff; the original Review in project brief and separate Use in brief actions remain responsible for it.

Each column links to its existing public project page and shows the published reference type, scope, visible workflow, dated screenshot, development attribution and evidence limitations. BANDEVI's own implementation remains labelled as an internal project; travel references preserve owner-supplied attribution and unpublished-responsibility limitations. Captured interfaces are explicitly dated and may differ from today's live site. Screenshots do not establish supplier access, successful bookings/payments, customer endorsements or measured business outcomes. No price, rating, delivery promise or unpublished client result is invented.

`scripts/public-project-comparison.json` contains only these reviewed public facts and four fixed existing image paths. The builder requires each text detail and capture date to appear in the corresponding existing canonical public HTML, checks tracked page/image paths and derives image alt text from the published image. It emits `assets/project-comparison-data.js`. The runtime validates exact keys, four approved project paths, bounded strings and exact approved screenshot paths before enabling the section. Unknown/private paths fail closed without affecting the original shortlist.

The table uses column/row headers and a caption naming the displayed references. A named, keyboard-focusable region allows horizontal scrolling on narrow screens; the page itself stays within the viewport. Its description includes the current comparison status, including stale-selection guidance. The screenshots load only when Compare constructs a table, from existing same-origin public assets. Their links open the original image in a new tab. The panel's focus and scroll offset accommodate the sticky header and mobile contact bar. Native public links and the existing no-JavaScript fallback remain available without the comparison module.
