# Public Site Search — 30 October 2026

The header and footer link to /search/. Visitors can enter a keyword and choose All content, Services, Projects or Guides. Typing and category changes are drafts; only Search or Enter applies them. Clear restores the initial directory, resets the controls and returns focus to the keyword. Results show a category, title, public excerpt and native page link. Zero matches show broader-term guidance and existing service/contact links.

The initial directory contains 55 explicitly approved public software-service, project and guide pages. The build reads only those tracked marketing HTML files, checks their public layout and canonical URLs, and embeds their existing public metadata. It does not crawl links or read customer records, private apps, live accounts or APIs. The Customer Portal result describes the existing public development-service page, not a signed-in customer account. Project labels distinguish the internal website project from public interface references.

Search runs locally against embedded public metadata. It makes no query requests and has no analytics, cookies, storage, history or CRM integration. Submitted text is rendered through textContent, matching uses normalized literal terms, inputs are bounded, and private/API URL families or invalid index entries disable filtering while retaining the original public links. The static directory and native links remain available without JavaScript. Search terms are not added to URLs or saved by this feature. Existing site analytics and enquiry workflows are unchanged.

Maintain scripts/public-search-pages.json deliberately. Run node scripts/build-site-search.cjs after approved metadata or directory changes. This updates only Search links on the 97 existing public marketing pages, the pure search renderer in assets/site.js, and search/index.html. No shared client or backend change is needed. The new search page uses noindex,follow and does not add parameterized pages to the sitemap.

Validation includes mechanical comparisons against production baseline 6f88cb98ade837bd8aa28b9847e571d05484d91d, deterministic build output, keyboard and WCAG checks, manual-only application, Clear, category isolation, relevance, empty results, inert markup-shaped queries, unchanged URLs/storage, zero API/write requests, invalid-index fallback, static/source parity, native links and mobile navigation. Chromium, Firefox and WebKit are covered; browser emulation is not a physical-device test. All existing CI gates remain, with a separate public-site-search gate. Deployment must preserve CRM permissions, reminders, ownership, private proposals, outgoing messages, service processes and routing.
