# Project Comparison Preview — 31 October 2026

The existing public Shortlist comparison gains **Preview comparison** and, inside the separate review panel, manual **Print / Save as PDF**, **Update preview** and **Close preview** controls. The required label is **Public project references — not a quotation.** Opening a preview does not print, send, download or persist anything. The browser's native print window is invoked only from the explicit Print / Save as PDF action. Its printer/PDF destination and final saving are controlled by the visitor.

The layer reads the existing displayed comparison and selected public references, without changing the comparison or shortlist controllers. A valid current comparison has two or three unique approved project URLs, the same selected checkboxes in the same order, and those references still present in the current shortlist. A snapshot includes that context and the displayed table signature. Changes to choices, a new comparison, removal or cross-tab clearing invalidate an open preview and disable printing until the visitor compares the current selection, updates the preview and reviews it again. Clear comparison closes and clears the preview; Close preview leaves the underlying comparison untouched.

Only the four existing approved public reference records and their fixed screenshot paths can supply content. The runtime checks exact keys, unique approved paths, image paths and bounded strings. The preview/print table contains public titles, types, scope, workflows, capture dates, development attribution and evidence limitations. Absolute source-page links are visible and clickable; screenshots link to their existing public assets. Unpublished delivery details, endorsements and business outcomes remain explicitly limited. The layer reads no visitor form fields, cookies, browser storage, hidden enquiry payloads, contact details, calendar data or CRM records, and makes no API or analytics calls.

The preview and a detached print copy use the same public snapshot. Both sets of screenshots must finish loading before printing is enabled. This allows the ready image nodes to be moved into the temporary paper root at the explicit print action, without relying on a fresh image load during printing. A failed screenshot blocks printing and offers manual Update preview; closing or changing context prevents a pending load from enabling an obsolete snapshot. Missing or throwing print APIs are handled without altering the shortlist or claiming that a PDF was saved.

Printing uses a temporary `#bgg-comparison-print` root and an explicit body state. Print CSS hides other body content, uses landscape A4 with 10 mm margins and a readable comparison table, and includes the exact label, public links, dated screenshot thumbnails and limitations. The paper root is cleared and print state removed on afterprint, print-media exit, close or reset. A context change during printing replaces the paper with an update-needed notice. The feature does not claim control over the visitor's native print menu, paper settings, physical printer or completed file-save operation.

The native screen preview remains responsive through a named keyboard-scrollable table region. Keyboard controls, status messages, required label, contrast and narrow viewport behavior are checked. The existing no-JavaScript fallback remains. Browser-native PDF samples for two and three references are checked with pypdf for complete text, label, landscape size, exact public link targets, screenshot counts and absence of visitor-content canaries. Rendered samples are inspected for clipping, pagination and legibility. The reviewed Chromium samples each fit on one landscape A4 page; user print settings and engines can affect pagination.

Only Shortlist receives the new CSS/JS bundle. Existing public reference data, comparison/brief controllers, backend and 99 other public pages remain unchanged. Older comparison boundaries remove only this exact additional bundle, while the new independent preview boundary compares all 100 pages and protected controllers with production `ce00d5a6050a398a1c46087629ad378f761c2719`.

Checks cover native/source pages, two/three references, separate review/print actions, stale selections, required Compare before Update, public-only print isolation, screenshot failures, unavailable/blocked printing, cross-tab context changes, idempotent initialization, cleanup, storage preservation and fallback. Live mode blocks non-GET/API requests and never sends a brief. Physical printers/devices and completed native save pickers are not claimed as tested.
