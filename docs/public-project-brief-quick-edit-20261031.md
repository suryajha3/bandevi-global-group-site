# Project Brief Quick Edit

Six keyboard-accessible Edit buttons beside review requirements focus the existing service, business type, problem, features, budget or launch-date field. Return to review runs both original step validation gates. Ordinary Continue and Back still work. Current requirements, contact details, country/currency restrictions, workflow and portfolio attribution remain in the original form.

This one-page additive module uses the existing navigation controls without changing their controller or the enquiry payload. It adds no storage, requests, tasks or automatic saving. Save draft remains manual; contact details remain excluded from saved drafts. Missing JavaScript leaves the existing navigation/fallback available.

The existing browser-only PDF preview remains labelled “Draft requirements — not a quotation.” Changes invalidate its snapshot. Update preview and another review are required before manual Print / Save as PDF. Preview/print exclude contact details. No CRM, reminders, customer messages, bookings, calendars, routing or other applications change.

Build with `node scripts/build-project-brief-quick-edit.cjs` after the existing public builders. Run `node scripts/qa-project-brief-quick-edit.cjs --all-browsers` with the pinned Playwright/axe runtime. Its independent baseline gate preserves all 100 existing public pages except the exact Brief asset bundle and compares every existing JavaScript/CSS/data asset, public builder and private server file. Browser checks cover six field targets, keyboard/focus, details and storage preservation, ERP labels, source attribution, text escaping, stale/updated print content, trim/required/date validation, both gates, maxlengths, sending/reset/fallback behavior, responsive layout and accessibility. Live mode blocks API and non-GET requests and never sends a brief. Existing CI suites remain enabled.
