# Bandevi inbox navigation and quick actions

Scope: Bandevi corporate sales inbox and client project handoff. This release changes frontend assets and isolated browser checks. THG public travel, hotel/flight suppliers, B2B and CRM products are outside this task.

The signed-in inbox has persistent navigation to Inbox, Projects, Proposals, Support, Demos, Reports and Settings. Reports, demo availability and account administration have separate views. Client project links remain visible after sign-in; the earlier login-only link is removed. Agents see only their permitted navigation and enquiry actions; existing server authorization remains authoritative.

Stage and follow-up counters are compact native buttons. A counter clears conflicting search/source/stage/follow-up filters and opens the corresponding inbox results from page one. Pressed state identifies the current counter filter. Reset filters and today's follow-ups are immediately available. Search/filter controls collapse on small screens and remain accessible through a native disclosure. Keyboard focus, meaningful headings, a skip link and wrapping mobile navigation are preserved.

Each enquiry has Open, Assign owner (administrators/managers), Follow-up and Project/proposal actions. Assignment and follow-up open the existing version-protected enquiry form and focus the relevant field; these actions do not save automatically. The project link supplies the enquiry reference and a suggested title. It selects the matching existing project. If that enquiry has no project, the creation form opens with that reference; another client's project is never silently selected. Proposal and support links scroll to their actual sections.

Pending loads retain the identity that issued them. Delayed administrator responses cannot populate a later agent session. Logout hides the navigation and clears private enquiry, team and editor values. A pending filter change is fetched again rather than silently discarded while an earlier request is loading.

Validation: twelve integrated browser scenarios cover signed-in navigation, enquiry position on desktop, separate views, stage filtering, keyboard follow-up filtering, assignment save/focus, follow-up focus, correct project selection, missing-project handoff, four responsive widths, logout, agent restrictions and delayed-response session isolation. The test fixture uses disposable SQLite records, synthetic credentials and no notification worker. GitHub runs these scenarios alongside the existing website and backend regressions.

Deployment: verify the current clean production revision and make a private application/configuration/environment archive and consistent SQLite backup. Fast-forward only `/srv/bandeviglobalgroup/app` to the exact tested merged revision. Existing asset endpoints read their frontend files per request, so this frontend release does not require a new route, database migration or service restart. Verify HTTPS assets, login shell, protected APIs and existing service/monitor/backup health. Preserve the current administrator credential configuration. On a source verification failure, restore the recorded clean baseline revision; retain the private database and configuration backups.
